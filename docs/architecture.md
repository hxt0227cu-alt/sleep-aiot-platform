## 二、硬件配置清单

| 模块 | 型号 | 功能说明 |
|------|------|----------|
| 主控芯片 | ESP32-S3 | 双核240MHz, WiFi+BLE, 主控核心 |
| 毫米波雷达 | R60ABD1 | 非接触式心率/呼吸/体动监测 |
| 音频功放 | MAX98357AETE+T | I2S数字功放, 驱动扬声器 |

| 负离子发生器 | 外接模块 | 12V供电, 空气净化 |
| LED光源 | PWM调光LED | 台灯照明, 色温亮度可调 |

## 五、技术栈选型

### 5.1 嵌入式固件
- **框架**: ESP-IDF v5.x (官方SDK)
- **RTOS**: FreeRTOS
- **语言**: C/C++
- **构建工具**: CMake + Ninja

### 5.2 后端服务
- **运行时**: Node.js 20+ LTS
- **当前实现**: NestJS 11.x + Express
- **语言**: TypeScript (原生支持)
- **ORM**: Prisma 5.x (类型安全的ORM)
- **数据库**: 
  - 时序数据: TimescaleDB (PostgreSQL扩展，SQL原生支持)
  - 关系数据: PostgreSQL (用户、设备信息)
  - 缓存: Redis 7.x (会话、热点数据、实时推送)
- **消息队列**: MQTT (设备通信) + Redis Pub/Sub (内部队列)
- **部署**: Docker + Docker Compose

### 5.3 小程序端
- **当前实现**: Taro 3.6.23 + React
- **语言**: TypeScript
- **图表**: ECharts for Taro (Apache ECharts官方Taro版本)
- **UI组件**: Taroify (Taro版Vant Weapp)

## 六、模块划分详细说明

### 6.1 嵌入式固件模块

#### 核心系统层
- **main**: 系统入口, FreeRTOS任务调度
- **board_config**: 硬件引脚定义, 外设配置
- **system_manager**: 看门狗, OTA升级, 电源管理

#### 设备驱动层
- **radar_driver**: R60ABD1 毫米波雷达驱动
  - 心率检测算法
  - 呼吸检测算法
  - 体动检测算法
  - 睡眠分期算法
- **audio_driver**: MAX98357A + ICS-43434 音频系统
  - I2S音频输出(功放)
  - I2S音频输入(麦克风)
 - 音频编解码
- **gsm_driver**: SIM800C GSM/GPRS模块
  - AT指令通信
  - 短信发送
  - 电话拨打
  - 网络连接(Fallback)
- **light_driver**: LED调光驱动
  - PWM调光(亮度)
  - 双色温控制
  - 渐变效果
- **anion_driver**: 负离子发生器控制
  - GPIO开关控制
- **voice_recognition**: 语音识别模块(混合方案)
  - 唤醒词识别(离线，ESP32-S3 AI加速引擎)
  - 简单命令识别(离线，如开关灯、调亮度)
  - 复杂命令识别(云端，如设置闹钟、查询报告)

## 八、技术栈优化说明（历史提案）

> 本节的技术栈、性能数字和选型结论是早期规划，未作为当前基准验证。当前实现为 NestJS 11 + Express、Prisma 5.22.0 和 Taro 3.6.23；当前容量与性能结论只认 `202607worklog/performance/` 中带有效原始证据的报告。

### 8.1 优化背景

以下内容记录当时的调研设想，不代表当前实现或已验证性能：

### 8.2 后端框架优化

| 项目 | 原方案 | 优化方案 | 优化理由 |
|------|--------|----------|----------|
| Web框架 | Express.js / Fastify | **NestJS 11.x + Express（当前实现）** | 企业级架构，模块化设计，依赖注入 |
| 语言 | JavaScript | **TypeScript** | 类型安全，开发体验好，NestJS原生支持 |
| ORM | 无/自建 | **Prisma 5.x** | 类型安全的ORM，自动生成类型定义，开发效率高 |
| 内部队列 | RabbitMQ/Redis | **Redis Pub/Sub** | 简化架构，Redis已用于缓存，复用连接 |

**性能说明**：早期框架对比数字没有保留可复现的环境与原始结果，不作为仓库证据。当前性能结论以 `202607worklog/performance/` 的报告和非空原始文件为准。

### 8.3 时序数据库优化

| 项目 | 原方案 | 优化方案 | 优化理由 |
|------|--------|----------|----------|
| 时序数据库 | InfluxDB / TimescaleDB | **TimescaleDB 2.x** | PostgreSQL扩展，SQL原生支持，统一数据库，运维简单 |

**性能对比**（基于实际测试）：

| 指标 | InfluxDB | TimescaleDB | 优势方 |
|------|----------|-------------|--------|
| 写入性能 | 基准 | ~80% | ⚠️ InfluxDB略优 |
| 存储空间 | 基准 | ~120% | ⚠️ InfluxDB略优 |
| 查询性能 | 良好 | 优秀 | ✅ TimescaleDB |
| SQL支持 | ❌ | ✅ | ✅ TimescaleDB |
| 数据修改 | ❌ | ✅ | ✅ TimescaleDB |
| 运维复杂度 | 需要独立运维 | PostgreSQL扩展 | ✅ TimescaleDB |
| 关系+时序JOIN | ❌ | ✅ | ✅ TimescaleDB |

**选型结论**：
- ✅ **主选TimescaleDB**：PostgreSQL扩展，无需额外运维，支持SQL查询，可JOIN关系数据和时序数据
- ✅ **单一数据库架构**：用户/设备数据和时序数据统一存储在PostgreSQL中
- ✅ **性能足够**：单设备10Hz采样，TimescaleDB完全够用

### 8.4 小程序技术栈优化

| 项目 | 原方案 | 优化方案 | 优化理由 |
|------|--------|----------|----------|
| 框架 | 微信原生 / Taro | **Taro 3.6.23 + React（当前实现）** | 多端支持，React生态，TypeScript支持 |

### 8.5 语音识别方案优化

| 项目 | 原方案 | 优化方案 | 优化理由 |
|------|--------|----------|----------|
| 识别方式 | 纯离线 | **混合方案** | ESP32-S3算力有限，复杂命令需云端 |

**混合方案设计**：

```
┌─────────────────────────────────────────────────────────┐
│                  语音识别流程                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  用户语音 --[ICS-43434]--> ESP32-S3              │
│       │                                               │
│       ├─> 唤醒词检测(离线，AI加速引擎)          │
│       │     └─> 唤醒成功，开始监听              │
│       │                                               │
│       ├─> 简单命令识别(离线)                    │
│       │     - 开关灯                                  │
│       │     - 调亮度/色温                            │
│       │     - 播放/停止白噪音                        │
│       │                                               │
│       └─> 复杂命令识别(云端)                    │
│             - 设置光闹钟                              │
│             - 查询睡眠报告                            │
│             - 语音合成(TTS)                            │
│             └─> [WiFi]--> 云端ASR服务 --> 返回结果    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**优势**：
- ✅ 离线命令响应快（<1秒），不依赖网络
- ✅ 复杂命令识别准确率高（云端ASR）
- ✅ 降低ESP32-S3算力压力
- ✅ 支持语音合成（TTS）功能
