# 密钥管理架构

## 概述

本文档定义睡眠监测平台的密钥管理架构，包括密钥生成、存储、使用、轮换和销毁的全生命周期管理。

## 架构设计

### 密钥分层架构

```
┌─────────────────────────────────────────────────────────┐
│                    应用层密钥                              │
│  (JWT 签名密钥、会话密钥、API Key、加密密钥)              │
└────────────────────────┬────────────────────────────────┘
                         │ 由 Vault 管理和分发
┌────────────────────────▼────────────────────────────────┐
│                    Vault (密钥管理服务)                    │
│  - 密钥存储 (KV v2)                                      │
│  - 动态密钥生成                                           │
│  - 密钥轮换                                               │
│  - 访问控制                                               │
│  - 审计日志                                               │
└────────────────────────┬────────────────────────────────┘
                         │ 主密钥由 KMS 保护
┌────────────────────────▼────────────────────────────────┐
│               阿里云 KMS (密钥管理服务)                    │
│  - 主密钥 (CMK) 存储在 HSM 中                            │
│  - 硬件级密钥保护                                         │
│  - 符合 FIPS 140-2 Level 3                              │
└────────────────────────┬────────────────────────────────┘
                         │ 根密钥离线存储
┌────────────────────────▼────────────────────────────────┐
│               离线根 CA (气隙环境)                         │
│  - 根 CA 私钥存储在离线 HSM                              │
│  - 仅在签发中间 CA 时使用                                │
│  - 双人控制，物理隔离                                    │
└─────────────────────────────────────────────────────────┘
```

### 密钥分类

| 密钥类型 | 用途 | 存储位置 | 算法 | 长度 | 轮换周期 |
|---------|------|---------|------|------|---------|
| 根 CA 私钥 | 签发中间 CA | 离线 HSM | ECDSA | P-384 | 10年 |
| 中间 CA 私钥 | 签发下级 CA | 在线 HSM | ECDSA | P-256 | 5年 |
| 设备 CA 私钥 | 签发设备证书 | 在线 HSM | ECDSA | P-256 | 2年 |
| 固件签名密钥 | 签名固件 | 离线 HSM | ECDSA | P-256 | 5年 |
| Vault 主密钥 | 加密 Vault 数据 | 阿里云 KMS | AES | 256 | 1年 |
| JWT 签名密钥 | 签名 JWT Token | Vault | HMAC | 256 | 90天 |
| 数据库加密密钥 | 加密敏感字段 | Vault | AES | 256 | 180天 |
| API 签名密钥 | 签名 API 请求 | Vault | HMAC | 256 | 180天 |
| 会话加密密钥 | 加密会话数据 | Vault | AES | 256 | 30天 |
| 设备通信密钥 | 设备端到端加密 | 设备 eFuse | AES | 256 | 设备生命周期 |

## 密钥生命周期管理

### 1. 密钥生成

**生成原则**:
- 所有密钥必须使用密码学安全的随机数生成器
- 密钥长度符合当前安全标准
- 密钥生成过程必须记录审计日志
- 私钥生成后不得明文存储或传输

**生成方式**:
```
# Vault 动态密钥生成
vault write -f transit/keys/jwt-signing-key type=hmac key_size=256

# KMS 主密钥生成
aliyun kms CreateKey --KeySpec AES_256 --Origin Aliyun_KMS

# 设备密钥（设备内部生成）
# 私钥在设备 eFuse 中生成，永不离开设备
```

### 2. 密钥存储

**存储要求**:
- 私钥必须加密存储
- 访问密钥需要身份认证和授权
- 密钥存储需要高可用和备份
- 密钥存储需要审计日志

**存储位置**:
| 密钥类型 | 存储方式 | 加密保护 |
|---------|---------|---------|
| 根 CA 私钥 | 离线 HSM | 硬件级 |
| 中间/设备 CA 私钥 | 在线 HSM | 硬件级 |
| Vault 主密钥 | 阿里云 KMS | 硬件级 |
| 应用密钥 | Vault KV v2 | KMS 加密 |
| 设备密钥 | 设备 eFuse | 硬件级 + 读保护 |

### 3. 密钥分发

**分发原则**:
- 密钥分发必须使用安全通道（TLS 1.2+）
- 密钥分发需要身份认证
- 密钥分发需要审计日志
- 最小权限原则

**分发方式**:
```
# Vault Agent 自动注入
# Pod 启动时通过 Vault Agent 获取密钥
# 密钥写入内存中的临时文件，Pod 停止时自动清除

# Kubernetes Secret (加密)
# 使用 Sealed Secrets 加密后存储在 Git
# 部署时由 Sealed Secrets Controller 解密

# 设备密钥
# 设备通过安全通道从云端获取会话密钥
# 设备主密钥在 eFuse 中，不通过网络传输
```

### 4. 密钥使用

**使用原则**:
- 密钥使用需要权限验证
- 密钥使用需要审计日志
- 密钥使用需要限流（防止滥用）
- 密钥不得记录到日志中

**使用控制**:
```
# Vault 策略控制访问
path "secret/data/jwt-signing-key" {
  capabilities = ["read"]
  allowed_parameters = {
    "key" = []
  }
  min_wrapping_ttl = "1h"
  max_wrapping_ttl = "24h"
}

# API 限流
# 密钥签名接口限流：1000次/分钟
```

### 5. 密钥轮换

**轮换原则**:
- 定期轮换（按密钥类型设定周期）
- 轮换过程不影响服务可用性
- 轮换需要双密钥过渡期（旧密钥继续可用一段时间）
- 轮换后旧密钥需要安全销毁

**轮换流程**:
```
1. 生成新密钥
2. 配置双密钥（新密钥用于签名，旧密钥用于验证）
3. 等待所有客户端更新到新密钥（过渡期）
4. 禁用旧密钥
5. 销毁旧密钥
6. 记录轮换审计日志
```

**自动化轮换**:
```yaml
# Vault 自动轮换配置
apiVersion: batch/v1
kind: CronJob
metadata:
  name: vault-key-rotation
spec:
  schedule: "0 0 1 */3 *"  # 每3个月
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: rotate
            image: vault:1.15.4
            command:
            - /bin/sh
            - -c
            - |
              vault login -method=kubernetes role=key-rotator
              vault write -f transit/keys/jwt-signing-key/rotate
```

### 6. 密钥销毁

**销毁原则**:
- 密钥销毁需要审批（双人）
- 销毁过程需要审计日志
- 销毁后需要验证无法恢复
- 销毁记录永久保存

**销毁方式**:
```
# Vault 密钥销毁
vault delete transit/keys/jwt-signing-key

# KMS 密钥禁用和销毁
aliyun kms DisableKey --KeyId <key-id>
aliyun kms ScheduleKeyDeletion --KeyId <key-id> --PendingWindowInDays 7

# eFuse 密钥（不可销毁，只能禁用）
# 通过 CRL 吊销设备证书
```

## 密钥访问控制

### RBAC 策略

| 角色 | 密钥读取 | 密钥写入 | 密钥轮换 | 密钥销毁 | 审计日志 |
|------|---------|---------|---------|---------|---------|
| 应用服务 | ✅ (特定密钥) | ❌ | ❌ | ❌ | 只读 |
| 运维人员 | ✅ (所有) | ✅ | ✅ | ❌ | 只读 |
| 安全管理员 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 审计员 | ❌ | ❌ | ❌ | ❌ | ✅ |

### 访问审批流程

1. **密钥读取**
   - 应用服务：通过 Vault 策略自动授权
   - 运维人员：需要主管审批
   - 安全管理员：自动授权（审计监控）

2. **密钥写入/轮换**
   - 需要运维主管审批
   - 操作需要双人在场
   - 操作过程全程记录

3. **密钥销毁**
   - 需要安全管理员审批
   - 需要工程经理审批
   - 操作需要双人在场
   - 销毁后 7 天等待期（可恢复）

## 密钥审计

### 审计日志内容

- 操作时间
- 操作人（身份）
- 操作类型（读取/写入/轮换/销毁）
- 密钥标识（Key ID，不记录密钥值）
- 操作来源（IP/服务）
- 操作结果（成功/失败）
- 失败原因（如失败）

### 审计日志存储

- 存储位置：独立的审计日志系统
- 保留期限：5年（合规要求）
- 完整性：哈希链，防止篡改
- 访问控制：仅审计员可访问

### 审计告警

- 异常时间访问（非工作时间）
- 异常来源访问（非预期 IP）
- 高频访问（可能滥用）
- 密钥轮换/销毁操作
- 访问失败次数过多

## 密钥备份和恢复

### 备份策略

| 密钥类型 | 备份方式 | 备份频率 | 保留期限 | 存储位置 |
|---------|---------|---------|---------|---------|
| 根 CA 私钥 | 纸质恢复码 + HSM 克隆 | 每次变更 | 永久 | 多地安全保管 |
| 中间 CA 私钥 | HSM 自动备份 | 每日 | 5年 | 异地 HSM |
| Vault 数据 | Raft 快照 | 每6小时 | 90天 | 对象存储 |
| KMS 主密钥 | KMS 自动备份 | 每日 | 1年 | KMS 内置 |

### 恢复流程

1. **根 CA 恢复**
   - 使用纸质恢复码恢复到新 HSM
   - 双人操作，全程审计
   - 验证恢复后密钥可用性

2. **Vault 恢复**
   - 部署新 Vault 集群
   - 从快照恢复数据
   - 使用解封密钥解封
   - 验证密钥可访问

3. **KMS 恢复**
   - 从 KMS 备份恢复主密钥
   - 验证密钥可用于加解密
   - 更新应用配置

## 合规要求

### 相关标准

- **FIPS 140-2 Level 3**: HSM 硬件安全模块
- **ISO 27001**: 信息安全管理体系
- **等保 2.0 三级**: 网络安全等级保护
- **GDPR**: 数据保护（如涉及欧盟用户）
- **个人信息保护法**: 中国个人信息保护

### 审计要求

- 密钥操作日志保留 5 年
- 每年进行一次密钥管理审计
- 每季度进行一次密钥访问权限审计
- 每月进行一次异常访问检查
