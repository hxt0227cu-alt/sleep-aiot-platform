# 灾难恢复 Playbook

## 概述

本文档定义睡眠监测平台的灾难恢复操作手册，涵盖各种灾难场景的恢复流程。

## 灾难分级

| 级别 | 描述 | 影响范围 | RTO | RPO | 响应级别 |
|------|------|---------|-----|-----|---------|
| P0 | 全区域故障 | 整个区域不可用 | 1小时 | 1小时 | CTO + 全团队 |
| P1 | 核心服务故障 | 核心服务不可用 | 30分钟 | 5分钟 | 值班主管 + 运维 |
| P2 | 非核心服务故障 | 部分功能不可用 | 2小时 | 15分钟 | 值班人员 |
| P3 | 性能下降 | 服务可用但性能下降 | 4小时 | - | 值班人员 |

## 通用恢复流程

### 阶段 1: 故障确认（5分钟）

1. 接收告警（PagerDuty/飞书）
2. 确认故障范围和影响
3. 通知相关人员（飞书群）
4. 创建故障事件（Incident）
5. 指定故障指挥官（Incident Commander）

### 阶段 2: 故障定位（10-30分钟）

1. 收集信息（日志/指标/链路追踪）
2. 定位故障根因
3. 评估影响范围
4. 制定恢复方案

### 阶段 3: 故障恢复（15-60分钟）

1. 执行恢复操作
2. 验证恢复结果
3. 监控服务状态
4. 通知用户（如需要）

### 阶段 4: 故障复盘（24-48小时）

1. 整理故障时间线
2. 分析根本原因
3. 制定改进措施
4. 更新 Runbook
5. 分享复盘报告

## 场景 1: 全区域故障

### 故障现象
- 整个可用区/区域不可用
- 所有服务无法访问
- 数据库连接失败

### 恢复步骤

1. **确认故障**（5分钟）
   - 确认云服务商状态
   - 确认故障范围
   - 通知所有团队

2. **切换到备用区域**（30分钟）
   - DNS 切换到备用区域
   - 启动备用区域服务
   - 恢复数据库（从备份）
   - 验证服务可用性

3. **数据同步**（15分钟）
   - 同步增量数据
   - 验证数据完整性
   - 切换读写到备用区域

4. **监控和验证**（10分钟）
   - 监控关键指标
   - 验证业务功能
   - 通知用户恢复

### 回切流程
- 主区域恢复后，等待稳定运行24小时
- 数据同步回主区域
- 逐步切换流量回主区域
- 确认主区域稳定后，停止备用区域

## 场景 4: 数据误删除

### 故障现象
- 误操作删除了重要数据
- 用户报告数据丢失
- 监控发现数据量异常下降

### 恢复步骤

1. **确认删除范围**（5分钟）
   - 确认删除的表和数据量
   - 确认删除时间
   - 停止相关写入操作（防止覆盖）

2. **从备份恢复**（30-60分钟）
   - 查找最近的备份
   - 恢复到临时数据库
   - 验证数据完整性
   - 将误删数据恢复到生产数据库

3. **使用 PITR**（如启用）
   - 恢复到删除前的时间点
   - 提取误删数据
   - 合并到生产数据库

4. **验证和通知**（10分钟）
   - 验证数据完整性
   - 通知受影响用户
   - 记录事件
