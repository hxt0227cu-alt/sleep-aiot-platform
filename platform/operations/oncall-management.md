# 值班管理规范

## 概述

本文档定义睡眠监测平台的值班管理规范，包括值班轮换、响应流程、升级机制和交接要求。

## 值班团队

### 团队组成

| 角色 | 人数 | 职责 |
|------|------|------|
| 主值班 (Primary On-Call) | 1人 | 第一响应人，处理所有告警 |
| 副值班 (Secondary On-Call) | 1人 | 主值班不可用时的备份 |
| 值班主管 (On-Call Lead) | 1人 | 复杂问题协调和升级决策 |
| 领域专家 (Domain Expert) | 按需 | 特定领域深度问题支持 |

### 值班轮换

- **轮换周期**: 每周轮换（周一 09:00 至下周一 09:00）
- **主副配对**: 主值班和副值班来自不同团队，避免单点故障
- **轮换日历**: 维护在飞书日历中，提前2周确定
- **换班规则**: 如需换班，需提前24小时通知并获得值班主管批准

## 响应时间要求

| 告警级别 | 响应时间 | 解决时间 | 通知方式 |
|---------|---------|---------|---------|
| Critical (P1) | 5分钟 | 30分钟 | PagerDuty + 飞书紧急 + 电话 |
| High (P2) | 15分钟 | 2小时 | PagerDuty + 飞书 |
| Medium (P3) | 1小时 | 8小时 | 飞书 |
| Low (P4) | 1工作日 | 3工作日 | 邮件 |

## 响应流程

### 1. 告警接收

1. 告警系统自动发送通知到值班人员
2. 值班人员确认收到告警（PagerDuty Acknowledge）
3. 如果5分钟内未确认，自动升级到副值班

### 2. 问题诊断

1. 查看告警详情和相关指标
2. 查阅对应的 Runbook（操作手册）
3. 初步判断问题范围和影响面
4. 如需要，拉相关领域专家进入故障群

### 3. 问题处理

1. 按照 Runbook 步骤执行修复操作
2. 如无对应 Runbook，记录处理步骤
3. 每15分钟更新一次故障进展（飞书群）
4. 修复后验证服务恢复正常

### 4. 故障记录

1. 在故障管理系统中创建故障记录
2. 记录故障时间、影响范围、处理步骤
3. 标记是否需要事后复盘（Post-Mortem）

## 升级机制

### 自动升级

| 级别 | 升级条件 | 升级到 |
|------|---------|--------|
| P1 | 5分钟未响应 | 副值班 |
| P1 | 15分钟未解决 | 值班主管 |
| P1 | 30分钟未解决 | 工程经理 |
| P1 | 60分钟未解决 | CTO |
| P2 | 30分钟未响应 | 副值班 |
| P2 | 2小时未解决 | 值班主管 |

### 手动升级

值班人员可随时手动升级问题，条件包括：
- 问题影响面超出预期
- 需要跨团队协调
- 需要管理层决策（如全量回滚）
- 涉及安全事件

## 交接要求

### 每日交接（工作日）

- **时间**: 每天 09:00 和 18:00
- **方式**: 飞书群文字交接
- **内容**:
  - 当前未解决的告警
  - 进行中的变更
  - 已知问题和临时规避方案
  - 待跟进事项

### 每周交接（轮换时）

- **时间**: 周一 09:00 - 09:30
- **方式**: 视频会议交接
- **内容**:
  - 上周故障总结
  - 未完成的跟进事项
  - 本周计划变更
  - 值班注意事项
  - 交接文档签字确认

## 值班补贴和调休

- 夜间值班（22:00-08:00）: 每次补贴200元
- 周末值班: 每天补贴300元
- 节假日值班: 每天补贴500元
- 调休: 周末值班可申请1天调休，需在1个月内使用

## 值班绩效评估

- 月度统计: 响应时间、解决时间、告警数量
- 季度评估: 值班质量评分（1-5分）
- 年度评选: 最佳值班工程师
